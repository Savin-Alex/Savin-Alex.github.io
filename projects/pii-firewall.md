Браузерное расширение, которое находит и обратимо маскирует персональные данные **прямо в браузере**, до того как промпт уйдёт в AI-чат (ChatGPT, Claude, Gemini, Perplexity, Poe), и восстанавливает исходные значения в ответе на компьютере пользователя.

Главное продуктовое решение — **zero network**: расширение не запрашивает сетевых разрешений и поэтому не может никуда отправить данные. Любой может проверить это заявление в `manifest.json`.

## Паспорт проекта

| Поле | Содержание |
|---|---|
| **Проблема** | Люди вставляют в AI-чаты договоры, документы и банковские реквизиты. Облачные «PII-фильтры» просят доверить те же данные ещё одному серверу. |
| **Цель** | Маскировать персональные данные до того, как они покинут страницу, с privacy-заявлением, которое пользователь может проверить сам, и восстанавливать их в ответе локально. |
| **В scope** | Движок детекции на TypeScript без зависимостей; 36 типов данных; обратимые плейсхолдеры; guard, который перехватывает отправку; popup и настройки; опциональное зашифрованное хранилище; интерфейс RU/EN; подготовка к Chrome Web Store. |
| **Вне scope** | Статус сертифицированного средства защиты информации; распознавание адресов; любая серверная обработка в бесплатной сборке. |

## Моя роль

**Роль:** IT Project Manager · соло-продукт; постановка задачи, архитектура, разработка и подготовка релиза.

- Выбрал zero network как основное обещание и ограничил разрешения до `storage`, `activeTab` и `contextMenus`.
- Задал уровни уверенности для каждого типа данных: голое число без контекста не маскируется с той же уверенностью, что ID с верной контрольной суммой.
- Подготовил релиз в магазин по политикам Chrome Web Store User Data и Limited Use.

## Как устроено решение

1. **Нормализация:** NFKC и снятие комбинирующих знаков, с картой смещений к исходному тексту.
2. **Фолдинг гомоглифов:** похожие кириллические буквы приводятся к латинице для латинских шаблонов, поэтому `еxample@mail` с кириллической «е» всё равно находится.
3. **Кандидаты → валидация:** кандидаты из regex проходят проверку контрольной суммы, формата или контекста (ИНН, СНИЛС, ОГРН, карта по Луну, IBAN mod-97, контрольные цифры MRZ, ID Китая по ISO 7064, Emirates ID).
4. **Разрешение перекрытий:** побеждает самый длинный фрагмент; при равенстве контрольная сумма важнее секрета, секрет важнее структурного шаблона, шаблон важнее имени.
5. **Маскирование и восстановление:** значения заменяются плейсхолдерами вида `[PERSON_1]` или `[RU_INN_1]`; ответ восстанавливается локально.
6. **Guard-режим:** перехватывает Enter и кнопку отправки и предлагает «замаскировать и отправить», «отправить как есть» или «отмена».

## Проверяемые сигналы

| Сигнал | Значение |
|---|---|
| Сетевые разрешения | **0** host permissions (Manifest V3) |
| Типы данных | 36: идентификаторы РФ, США, Великобритании, Китая и ОАЭ, карты, IBAN, SWIFT, MRZ паспорта, IP-адреса, секреты и ФИО с учётом падежей |
| Автотесты | 117 тестов (контрольные суммы, детекторы, корпус, хранилище, настройки, i18n, content script) |
| Синтетический корпус | 123 случая с позитивами и негативами-«ловушками»; без реальных персональных данных |
| Релиз | Собран пакет v0.5.0; черновик карточки магазина на RU |

## Реестр рисков

| Риск | Контроль / следующий gate |
|---|---|
| Имя или ID пропущены | Ограничения названы прямо: распознавание имён эвристическое; корпус растёт с каждым новым детектором и его негативами |
| Число замаскировано по ошибке | Уровни уверенности зависят от контекста; шумные типы, например дата рождения, по умолчанию выключены |
| Пользователь считает расширение сертифицированным средством защиты | README и карточка магазина прямо говорят, что это не сертифицированное средство |
| Будущий платный тариф нарушит обещание zero network | Командный режим спроектирован как opt-in и self-hosted и описан отдельно от zero-network-сборки |

## Статус и следующий gate

**Статус: Amber / release candidate.** Пакет v0.5.0 и чеклист готовности к магазину готовы. Новые детекторы для Великобритании, MRZ, Китая и ОАЭ ещё не выпущены.

Следующий gate: публикация в Chrome Web Store, затем измерение жалоб на ложное маскирование и пропуски от реальных пользователей.
