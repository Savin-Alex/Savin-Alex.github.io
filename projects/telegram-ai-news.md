LLM-пайплайн контента и локальная операторская консоль для русскоязычного Telegram-канала про ИИ. Это не агрегатор «всего подряд»: раз в 15 минут он читает источники, отбирает и оценивает инфоповоды с помощью LLM и пишет черновики. Сейчас канал работает **без присмотра**, и ограничители, которые делают это безопасным, заложены в коде, а не в человеке.

Кейс про генеративный ИИ как управляемый процесс: поэтапные LLM-вызовы со structured output, код, который может только ужесточить решение модели, жёсткая граница затрат и ограничители, которые сужают возможности автоматического запуска.

## Паспорт проекта

| Поле | Содержание |
|---|---|
| **Проблема** | AI-каналы либо пересказывают пресс-релизы, либо публикуют всё подряд. Тем, кто строит продукты с ИИ, нужно меньше постов, но с источниками, цифрами и скептическим комментарием. |
| **Цель** | Каждый пост за 30 секунд объясняет, что случилось, почему это важно практикам и на какую цифру или источник можно нажать. |
| **В scope** | Сбор RSS из управляемых источников (сейчас включены только источники высшего доверия); дедупликация; LLM extract → score → synthesize; очередь черновиков и слоты дайджеста; операторская консоль на localhost; редакционные политики; статический архив; отчёт по затратам и использованию. |
| **Вне scope** | Охват всего рынка ИИ; роль самого быстрого агрегатора; переход по ссылкам за полным текстом статьи; генерация обложек в v1. |

**Проверяемая гипотеза v1:** русскоязычная аудитория, которая уже следит за ИИ, ценит фильтр больше, чем объём.

## Моя роль

**Роль:** IT Project Manager · соло-продукт; постановка задачи, архитектура, разработка и эксплуатация.

- Написал обещание читателю, список «чего не обещаем» и редакционные политики (исправления, спонсорство, приватность, доверие к источникам) до начала роста.
- Зафиксировал 20 проектных решений с компромиссами — от «многоэтапный пайплайн вместо одного мега-промпта» до «при ошибке скоринг всегда возвращает SKIP».
- Задал release gates: до запуска публикация только с одобрением, security-аудит до запуска, CI с установкой зависимостей по lock-файлу. Автоматическая публикация появилась позже и только со своими ограничителями.

## Как устроено решение

```
RSS → Fetch → Dedup → Extract (Haiku 4.5) → Score (Haiku 4.5)
                                               ↓
                                  SKIP · WRITE_QUEUE · WRITE_NOW
                                               ↓
                              Synthesize (Sonnet 5) → Черновик
                                               ↓
  Источник высшего доверия: публикуется · любой другой: остаётся черновиком
                                               ↓
                                  Telegram / слот дайджеста
```

- **Один LLM-вызов на этап**, у каждого structured output. Промпты лежат в текстовых файлах, поэтому редакционные правки не требуют правки кода.
- **Дешёвые модели фильтруют, сильная пишет:** Haiku 4.5 извлекает факты и оценивает; Sonnet 5 пишет только прошедшие посты. Для каждого этапа есть локальная альтернатива на Ollama.
- **Правила доверия в тексте:** каждая цифра ведёт на источник; источники с низким доверием (tier-3) получают префикс «по слухам»; фиксированная таксономия из 8 категорий.

## Контроли

| Контроль | Как работает |
|---|---|
| Режим публикации | Два режима: с одобрением и автоматический. Консоль стартует на паузе, а переход в автоматический режим требует ввести подтверждение. Сейчас канал работает автоматически |
| Ограничители для работы без присмотра | Включены только источники высшего уровня доверия (tier 1), и только они могут публиковаться сами. Любой менее доверенный источник остаётся черновиком для человека. Не более 10 автоматических постов за запуск — это аварийный стоп |
| Граница prompt injection | Содержимое фидов передаётся как данные; код пересчитывает оценку и может только понизить вердикт модели; оценка вне диапазона даёт `SKIP` |
| Целостность ссылок | Кнопки источника привязываются к реальному источнику новости; inline-ссылки должны вести на новость или её извлечённые цифры |
| Граница затрат | В LLM-пайплайн попадают только источники до заданного уровня доверия; каждый LLM-ответ записывается с моделью, этапом, токенами и стоимостью |
| Circuit breaker по оплате | Ошибки авторизации или оплаты (401/402) открывают постоянный breaker и останавливают новые запуски; отсечка backlog не даёт платить за устаревшие повторы после восстановления |
| Безопасность загрузки | Защита от SSRF: каждый редирект проверяется, соединение привязано к проверенному IP, размер ответа ограничен |

## Реестр рисков

| Риск | Контроль / следующий gate |
|---|---|
| Prompt injection через новость в фиде | Полностью устранить нельзя. Включены только источники высшего доверия, код может только ужесточить вердикт, а лимит на запуск ограничивает ущерб |
| Неверная цифра доходит до читателя | Каждая цифра должна вести на источник; письменная политика исправлений (реплай к посту, без тихого удаления) |
| Затраты на LLM растут без ценности | Граница по уровню доверия, учёт стоимости по этапам и breaker по оплате |
| Рост раньше доверия | Редакционная и спонсорская политики написаны до публичного запуска |
